# Singapore PSI +3-Hour Forecast Dashboard

A responsive Streamlit capstone dashboard showing **official NEA observations** for Singapore's five PSI regions and, after validation, an **experimental 3-hour-ahead 24-hour-PSI forecast** from the provided weather-enhanced XGBoost `.joblib` artifact.

> Research demonstration only. Not an official NEA forecast, health advisory or operational warning service.

## 1. Model audit

The uploaded trusted artifact, `models/psi_weather_xgboost.joblib`, is a dictionary containing `pipeline`, 60 numeric feature names, one categorical `region`, a feature order, and metadata. The pipeline includes a fitted `ColumnTransformer` and `XGBRegressor`. Recorded versions are **scikit-learn 1.9.1** and **XGBoost 3.2.0**. Training period: **2019-2023**. Target: `psi_3h_ahead`.

The previously reported 2024 matched-sample test MAE was **1.308575** for the weather model and **1.346563** for the matched control. These retrospective results have **not been independently reproduced** in the live app environment.

## 2. Install and run

Python 3.13 recommended. In the project root:

```bash
python -m venv .venv
source .venv/bin/activate              # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
streamlit run app.py
```

For more reliable rate limits, create `.streamlit/secrets.toml` locally (do not commit it):

```toml
NEA_API_KEY = "your-personal-data-gov-sg-api-key"
ENABLE_FORECAST = false
```

The observation dashboard will work without enabling inference, provided the official APIs are reachable and their schemas remain compatible.

## 3. Before enabling live forecasts

**Forecasts intentionally default to disabled.** The joblib's presence alone cannot establish that the historical feature engineering and live API feature reconstruction are identical. The live environment and actual historical API payloads could not be reached during project construction.

1. Confirm Streamlit successfully loads the artifact under the exact pinned package versions.
2. Verify the NEA v2 PSI API exposes all seven pollutant/PSI fields required by the saved model for every region.
3. Verify 24+ hours of complete hourly historical PSI and 6+ hours of complete regional weather can be retrieved with daily date queries and pagination.
4. **Check feature parity against an actual historical training snapshot**: for one timestamp/region, compare each of the 61 features generated by `src/features.py` with the saved training-notebook feature row. Check the PSI and weather units, 15-minute PSI reduction to hourly, `rolling` inclusion, region-coordinate assignment, time of availability, and hour/weekday encoding. The weather aggregation in the last notebook uses next-hour availability and last station reading per hour.
5. Confirm a known input row produces the exact same model output with the pinned dependencies as it does in the original environment. Check per-feature numerical tolerances and prediction tolerances.
6. Review station coverage and sampling across all five PSI regions. Record the verification results in the project documentation.
7. Only after that verification, set `ENABLE_FORECAST = true` in Streamlit Secrets.

If data gaps, API changes, model version differences or other validation failures occur, **no forecast should be shown**. Do not replace missing lag values with zeros or fake readings.

**Known potential parity gap:** the training notebook's detailed base-feature rolling definitions and current-hour availability require comparison against the original training cells. The code offers a documented reconstruction, not a certified reproduction. The UI intentionally distinguishes live NEA observations from model outputs.

## 4. Data retrieval and update frequency

- Real-time endpoints: `https://api-open.data.gov.sg/v2/real-time/api/psi`, `wind-speed`, `wind-direction`, `air-temperature`, `relative-humidity`, and `rainfall`.
- Daily requests use `?date=YYYY-MM-DD`, with pagination support when the API returns a token.
- NEA PSI typically updates every **15 minutes**; other environmental variables can update on different schedules.
- Active Streamlit sessions rerun the live section every **15 minutes** using `st.fragment(run_every='15m')` and cache official responses for 900 seconds.
- There is **no background collection** while the web application is asleep. Historical API calls rebuild features on demand. This may be slow or rate-limited for public traffic.
- The dashboard displays timestamps and stale-data warnings, and withholds inference when data cannot be assembled.

## 5. Model input features

- Air-quality: 7 pollutant/PSI measurements, longitude, latitude, cyclic time, weekday, 6 PSI lags, 3 PM2.5 lags, rolling means and variation, changes.
- Weather: latest hourly regional wind speed, rainfall, temperature, humidity and sin/cos of wind direction; 1h/3h/6h lags and 6h rolling means for each of six weather components.
- One categorical feature: `region`.

Weather station location matching uses the nearest region reference coordinates provided by NEA. This is an approximation, not an official polygon assignment.

### Forecast input compatibility fix (October 2026)

The hourly weather aggregation labels observations from hour `h` as available at
`h+1`. The newest PSI timestamp can therefore be newer than the latest usable
weather timestamp. The dashboard now checks the latest overlapping completed
hour, within a three-hour freshness limit, and reports the reasons if no valid
forecast origin can be assembled. Historical weather lag gaps are handled by
*the already-fitted model imputer*, rather than fabricated values. Current
weather readings and 24-hour PSI history remain required. This update has
passed local unit tests but still needs a live NEA and training-row parity check.

To investigate an unavailable forecast, open **Technical reason** in the
Streamlit dashboard and copy the detailed error. A forecast will not be shown
when current readings or essential PSI history are unavailable.
